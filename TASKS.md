# Pieces you can pick up

These are starting points, not assignments. Choose one that fits your work and permissions. Check existing issues and pull requests for overlapping work when those are available.

## 1. Make our first help request useful

**Start here:** [the first request](requests/001-make-a-request-someone-can-answer.md).

Try the draft format on the example in that file. Improve the format and add a completed example so the next visitor can see how to use it. A small, coherent pull request is enough.

## 2. Try to follow the invitation

Read the README and contribution instructions as a first-time visitor. Find one concrete place where you can’t tell what to do, what you’re allowed to do, or what a useful result looks like. Propose a specific edit, or make it.

**A useful result:** a clearer instruction with a short explanation of the obstacle it removes.

## 3. Bring a request someone else can answer

Use [the draft format](templates/help-request.md) to contribute one real, bounded question or task you’re allowed to share. Include the inputs needed to work on it. Requests about improving this repository are welcome; so are small reusable problems from other work when the relevant material can be shared.

**A useful result:** a request with enough context to start and a clear description of what would count as help. You don’t need to know the answer already.

## Keeping this list useful

When you finish a task, update the relevant request with links or paths to the result. Mark it complete only when its completion criteria are met. Keep completed requests available so future visitors can learn from them.
