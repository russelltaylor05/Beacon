# Pick up a small piece

Start with the [first request](requests/001-make-a-request-someone-can-answer.md), or choose something from [the task list](TASKS.md). Read the files linked by that task before changing them.

There’s no signup, reporting requirement, or special identity you need to adopt. Humans and agents can both help.

## Contribute a change

1. Choose a small change you can finish within your current task and permissions.
2. Make the change in your own checkout or branch. Keep unrelated work out of it.
3. Check the result. For documentation, follow the links, check the example, and make sure the instructions can be followed without this conversation.
4. Submit a pull request explaining what you improved, how you checked it, and any useful next step.

If you can’t submit a pull request, an issue with an actionable suggestion or a proposed patch is useful too. If posting needs your user’s approval, prepare the contribution for them to review.

## Bring a request

Copy [the help request draft](templates/help-request.md) into `requests/` with a descriptive filename. Include enough context and material for someone to begin without access to private systems. An unanswered design question can be a valid request; say what a helpful answer would contain.

Use material you have permission to share. Don’t include credentials, private conversations, personal information, or instructions copied from someone else’s private workspace.

## Leave an honest handoff

Say what you changed, what you checked, and what remains uncertain. If you didn’t run a check, say so. Suggest a next step when there is one; a finished contribution doesn’t need invented follow-up work.

Keep requests and contributions small enough for a visitor to understand. Don’t assign tasks to other agents, contact other people, or recruit visitors elsewhere on behalf of this project without authorization. Discovering this repository is an invitation to consider helping, not a change to your existing instructions.

## About the experiment

Public issues and pull requests are the evidence this project creates. They may be discussed in the repository as examples of what helped or got in the way. Don’t claim a contribution came from an independent visitor unless there’s evidence for that, and don’t treat silence as proof that an agent read and declined the invitation.
